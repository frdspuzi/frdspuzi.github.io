## Recent Work

**YouTube carousel VideoCard refactor (2026-08-07).** After fixing one real bug in the old prev/current/next architecture (a `p-4` class's `!important` padding silently beating a non-important React inline style, making the "current" card ~12px shorter than the preview slides for the same video), the user reported the swap still wasn't quite seamless — text/badges shifting position right at the moment a preview became current. Further static-analysis debugging didn't turn up a second discrete bug. The user proposed rendering prev/next as the same real card component instead of a simplified preview — recognized as the architecturally correct fix (it doesn't patch the discrepancy, it removes the only place it could come from) and implemented: one `VideoCard` component, rendered 3x and keyed by `video.videoId`, relying on React's keyed-list reconciliation to move/preserve each card's state as the 3-video window slides on swipe. Peek (non-active) cards render identical markup to the active card but are inert — no click/keyboard handlers wired, `tabIndex={-1}` — per explicit user confirmation ("inert until active"). `currentIndex` is now real `useState`; the track's instant transform-reset on commit moved from inline-in-the-swipe-`setTimeout` into its own `useLayoutEffect` keyed on `[currentIndex]`, so it's guaranteed to run only after React has already re-rendered the new video into the center slot (doing the reset first, before the state update flushes, would show the old video freshly recentered for a frame before flashing to the new one). Also added a shared module-scoped YouTube IFrame API loader, since API access is no longer tied to one hardcoded card.

**A run of visual bug reports (2026-08-06/07)**, each investigated via CSS/spec reasoning rather than a visual tool (no browser access this environment — see Verification notes) and fixed:
- Avatar/map-pin misalignment — Tailwind Preflight forces `img`/`svg` to `display:block`, breaking Primer's inline-flow/`text-align:center` assumptions. Fixed with `margin:0 auto` (img) / explicit `display:inline-block` inline style (svg — inline style beats a plain element-selector rule regardless of import order).
- YouTube facade thumbnail invisible — `.yt-facade`/`.yt-facade-thumb`/`.yt-facade-play` were never actually centralized into `site.scss`, only present in the original's own `<style>` block; an earlier grep match on the other two terms wrongly suggested full coverage.
- Medium articles horizontal-scrolling — `#medium-posts` (a flex item) had no `min-width:0` (flex default is `min-width:auto`), plus `overflow-y:auto` with no explicit `overflow-x` computing to `overflow-x:auto` per spec.
- Added a full-bleed animated shader background to Masthead's hero (`position:absolute; left:50%; width:100vw; transform:translateX(-50%)` breakout pattern, `body{overflow-x:hidden}` needed since 100vw includes scrollbar width) — required fixed (non-theme-reactive) text/icon colors since the shader doesn't respond to the toggle the way the surface it replaced did.
- Aurora-text gradient loop seam — `animation:infinite` snaps from the last keyframe color straight back to the first on every loop; fixed by repeating the first color as a final gradient stop (the user has since further hand-tuned the palette directly).
- Dark-mode-by-default — `index.html`'s `data-theme` and `useTheme.ts`'s SSR-guard fallback both flipped from `light` to `dark`.
- Theme-toggle view-transition not covering short pages — `.min-height-full`'s `min-height:100%` had no definite-height ancestor to resolve against (`<html>`'s own height is auto/content-sized by default), which also silently broke the View Transition API's root-snapshot sizing. Fixed with `html{height:100%}`.
- Missing About section — `index.html`'s own markdown body was never ported at all (rendered via a separate Jekyll template context from `masthead.html`, easy to miss). Built as `AboutContent.tsx` after the user asked "where's my about section?"

**The accordion animation bug chain (2026-08-06)** — read architecture.md's invariants before touching this system again; that section is the narrative behind them. Root cause: `open` state used to be seeded by a mount-effect calling `toggle()` a render after the accordion's own first render, so every `defaultOpen` accordion's `open` lagged `true` by one render, cascading into a mobile force-close race, a stale-animation-clobbers-the-fix bug, and (from an interim attempted patch) a reactive-`display`-races-imperative-WAAPI-code regression. Real fix: `isOpen`/`toggle` now take the caller's own `defaultOpen` prop directly as a fallback, correct from render 1; `useAnimatedDisclosure` became sole owner of `display`, switched to `useLayoutEffect`.

**Component-sourcing rule**, established mid-session and applied to every section since: check beui/magicui/aceternity/shadcn registries first, verify actual source (not just name) before concluding fit. Confirmed real matches: `@beui/preview-rail` (the floating nav). Confirmed non-fits, ruled out after reading actual source: `bouncy-accordion` (single-open-only, doesn't fit 3 independent multi-open-on-desktop sections), `@beui/infinite-masonry` (virtualized vertical list, not a 2D drag-pan canvas).
